# 插件系统与权限管理体系扩展需求文档

> **状态声明（2026-09 更新）**：本文为早期需求文档。当前实际实现：知识库已**不再作为插件**（抽取为门户默认功能，见《门户布局与功能改造需求文档》§14）；**注册已屏蔽**（仅站主手动建号，见 `POST /api/auth/users`）；插件商店/管理、站主管理、三端布局等按「现状总览」执行。本文仅作为设计背景参考。

## 1. 项目背景

现有网站已具备 AI Agent、知识库等核心功能，但功能模块相对固定，缺乏灵活性与个性化配置能力。为提升平台的可扩展性、用户体验与运营管理效率，现计划引入插件化架构与多角色权限体系，将现有功能模块统一封装为可管理的插件，并支持站主按需配置功能显示，同时为不同角色用户提供差异化的访问能力。

## 2. 功能需求

### 2.1 插件系统

- 建立标准化的插件架构，支持功能的独立安装、卸载、启用、禁用与更新。
- 插件应具备统一的配置界面、版本管理与依赖检测机制。
- 提供插件生命周期管理，包括初始化、运行、停用和销毁阶段。
- 插件需声明所需权限，并遵循权限校验流程。

### 2.2 权限系统

- 引入多角色体系，至少包含以下三种角色：
  - **游客**：未登录状态自动识别，拥有最低访问权限。
  - **注册用户**：登录后获得基础用户权限，可访问被授权的插件与功能。
  - **站主（管理员）**：拥有最高管理权限，可管理插件、用户及系统配置。
- 默认不登录即可浏览公开内容，但受限插件或功能对游客隐藏或禁用。
- 支持用户注册、登录、个人信息管理及密码找回等基础账号功能。
- 站主可管理用户账号，包括禁用、删除、角色调整等操作。

### 2.3 插件显示配置

- 站主可在后台管理界面中，配置每个插件在功能区（前台展示区域）的显示或隐藏状态。
- 显示配置支持按角色维度区分，例如：
  - 游客可见：仅展示公开插件。
  - 用户可见：登录后展示额外授权插件。
  - 站主可见：所有插件均可见，含管理入口。
- 提供可视化配置界面，支持开关切换、拖拽排序，并实时预览前台效果。
- 配置修改即时生效，无需重启服务或重新部署。

### 2.4 插件商店

- 构建插件商店页面，展示官方及第三方提供的可用插件列表。
- 每个插件应包含详情页，展示功能说明、版本信息、兼容性、截图及用户评价等。
- 支持插件搜索、分类筛选、评分与评论（可选）。
- 站主可一键安装、更新或卸载插件；普通用户仅可浏览商店，安装权限由站主控制。
- 插件商店需具备安全审核机制，防止恶意插件上架。

### 2.5 插件导出功能

- 支持将已安装插件的配置及关联数据打包导出，格式可采用 JSON 或专用压缩包。
- 导出内容应包含：
  - 插件列表及版本号
  - 各插件的启用状态与自定义配置
  - 权限角色关联设置
- 导出文件可用于备份、迁移至其他站点，或分享给其他站主导入使用。
- 可选支持仅导出插件本体（不含数据），便于二次分发。

### 2.6 默认插件与功能区集成

- 将现有 **AI Agent** 与 **知识库** 功能改造为系统默认内置插件。
- 系统初始化时自动安装并启用这两个默认插件，显示在功能区默认位置。
- 站主可通过插件显示配置功能，调整其显示/隐藏状态或排序，但默认插件不可被卸载（可禁用）。
- 后续新增的核心功能也应优先以默认插件形式集成，保持架构统一。

## 3. 非功能需求

- **性能**：插件加载与切换不应显著增加页面响应时间，需支持懒加载或按需加载机制。
- **安全**：
  - 所有插件必须经过权限校验，防止越权访问。
  - 插件上传与安装需进行安全扫描，防止代码注入或恶意操作。
  - 导出数据支持可选的加密保护。
- **兼容性**：
  - 插件系统需兼容主流浏览器（Chrome、Firefox、Edge、Safari 最新版本）。
  - 支持响应式布局，适配桌面与移动端展示。
- **可扩展性**：
  - 插件接口设计应预留扩展点，允许第三方开发者自定义插件类型。
  - 权限体系支持后续扩展更多角色或细粒度权限项。

## 4. 验收标准

1. 游客未登录访问网站时，仅能看到站主配置为“游客可见”的插件功能区。
2. 站主在后台修改任意插件的显示/隐藏状态后，前台功能区实时同步更新。
3. 插件商店可正常展示、安装、更新、卸载插件；默认插件可被禁用但不可卸载。
4. 导出的插件配置包可被重新导入，并完整还原插件启用状态与设置。
5. 现有 AI Agent 与知识库功能在升级后，作为默认插件正常显示在功能区，且原功能无回归问题。
