# i-kit 门户布局与功能改造需求文档

> 版本：v0.2（as-built）
> **本文档说明**：第 1–13 节为参考站分析与需求设计；**§14「现状总览」为当前实际实现记录（以代码为准）**。其他历史文档（PRD / 插件系统需求）中的现状说明同样以此为准。
> 范围：**只改布局 + 只增功能**；保留本项目全部既有功能（知识库 / AI Agent / 插件商店 / 系统 / 用户管理 / 数据统计 / 便签 / 日历 / 待办 / 天气 / RSS / Markdown 剪贴板等）。
> 前置约束（已落实）：登录改为「点击头像弹登录框」，注册已屏蔽（站主手动建号）。完成前不自动提交/部署。

---

## 1. 背景与目标

当前 i-kit 的前台是「控制台 / 面板」形态：顶部导航 + 主区切换 + 移动端底部 Tab。用户希望参考**某知识门户站点**（Typecho 主题风格）的**三栏门户式布局**，把既有功能包裹成更接近「内容站点 / 知识门户」的体验，并借鉴其特色功能。

**坚持的原则**
- 既有功能一个都不删，只调整呈现方式与入口。
- 新增功能与布局改造分开推进，先文档、后分层实施。
- 站主（admin）功能与普通用户（前台）功能保持隔离。

## 2. 参考站布局与功能分析

> 依据浏览器实测（截图 + DOM）。该参考站采用 Typecho 博客主题，核心形态如下。

### 2.1 整体结构：三栏门户
```
┌─────────────────────────────────────────────────────────┐
│ Header：Logo + 站名 | 快捷入口(小店/FRP/RSS/TG群/仓库)     │
│          | 全局搜索(Ctrl+K) | 右上角头像                   │
├──────────┬────────────────────────────┬──────────────────┤
│ 左侧导航  │     主内容（卡片流 feed）      │   右侧 widget 列  │
│ - 站签名   │  - 封面大图卡片，标题叠加     │  - 热门文章       │
│ - 分类树   │  - 摘要 / 作者/时间/浏览/标签 │  - 最新评论       │
│ - 专栏/专题 │  - 分页                    │  - 动态日历       │
│ - 页面链接  │                            │  - 统计图表(雷达/柱状)│
│ - 快捷链接  │                            │  - 标签云         │
└──────────┴────────────────────────────┴──────────────────┘
                        页脚
```

### 2.2 关键布局特征
1. **顶栏**：左 Logo+站名；中间一组快速功能入口（小店/FRP/RSS/TG群/仓库 等外链按钮）；**全局搜索**（占位「搜索（Ctrl + K）」）；极右**头像**（本布局用于登录/个人中心）。
2. **左栏**：竖向导航。顶部一句博主签名 moto；下方是**多级分类树**（如 分类 → 日常资讯/数字生活/运维部署/技术教程/群晖专栏，专栏再分 基础/网络/套件/高级）。再往下是「页面」组（留言板 / 归档库 / 关于我）和「快捷入口」（小店/FRP/RSS/仓库）。
3. **中栏**：**卡片流**。每条卡片 = 封面大图（标题压图、渐变遮罩）+ 正文标题 + 摘要 + 元信息（作者 / 时间 / 浏览数 / 标签 / 分类）。鼠标悬停有位移/阴影动效；底部为分页。
4. **右栏**：**widget 堆叠**。热门文章、最新评论、动态日历、博主发布/评论月统计、**分类雷达图**、**发布统计图**、标签云。整体可折叠。
5. **响应式**：窄屏时左/右栏收起为抽屉，主内容单列。

### 2.3 可借鉴的「功能点」
来自实测提取：
- 多级分类导航（分类树、专栏/专题分组）
- 卡片式内容流（封面 + 标题压图 + 摘要 + 元信息）
- 全局搜索（支持 Ctrl+K 呼出）
- 阅读/浏览计数（"N 次浏览"）
- 热门文章 widget、最新评论 widget、标签云
- 动态日历 widget（近月发布热点日历）
- 统计图表 widget（分类雷达图、发布柱状图、近 10 月发布/评论统计）
- 「专栏/专题」策划（类似知识库的专题合集）
- 页面链接：留言板、归档库、关于我
- 站签名 moto、博主形象位（左栏头像/签名）
- 分页、文章作者/时间/标签元信息排版

## 3. 现状盘点（i-kit 已有）

| 模块 | 现状 | 归属 |
|---|---|---|
| 知识库 | CRUD / 混合检索 / 分类树 / 回收站 / 置顶 / 导出 / 版本 / AI 摘要 / 评分 / 点赞 / 分享 / 状态 | 功能插件 `knowledge` |
| AI Agent | 工具 + RAG + SSE 流式对话 | 功能插件 `agent` |
| 插件商店 | 浏览/安装/更新/卸载/评分/评论；**签名状态徽标**（已验证 / 已签名·装机时验证 / 未签名 / 验签失败，`enforce` 下按钮禁用并给出原因） | 站主 `store` |
| 插件管理 | 启用/停用/配置 | 站主 `manager` |
| 系统 | 系统信息/更新/健康 | 站主 `system` |
| 用户管理 | 列表/角色/重置/禁用（**尚无站主手动加号**） | 站主 `users` |
| 数据统计 | 汇总计数 | 功能插件（商店）`stats` |
| 便签 / 日历 / 待办 / 天气 / RSS / MD剪贴板 | 独立功能面板 | 功能插件（商店） |
| 登录/注册 | AuthPanel（登录+注册+找回） | 全局 |

**当前布局**：单行顶栏（仅 admin 有「管理」下拉分组）+ 主区切换 + 移动端底部 Tab。非站主默认落第一个功能插件。

## 4. 总体改造方向

把「前台功能区」从「控制台」升级为「**知识门户**」三栏布局，站主管理收敛到独立的后台/分组；登录走头像弹框。

```
新前台（普通用户 / 站主皆可见）
├── 顶栏：Logo+站名 | 快捷入口 | 全局搜索(Ctrl+K) | 头像(登录弹框) | 暗色切换
├── 左栏：我的/知识库/Agent/… 功能插件导航（分类树化） + 页面(归档/关于/留言)
├── 中栏：知识卡片流（默认 tab）+ 具体功能面板（Agent→对话流、统计→卡片、便签…）
└── 右栏：热门文章 / 最新评论 / 标签云 / 动态日历 / 统计图表（widget 化）

站主后台（仅 admin，独立分区）
├── 系统 / 插件管理 / 插件商店 / 用户管理（保留现有，入口收敛）
```

**关键点**：功能插件（knowledge/agent/stats/notes/…）仍是 `tab` 切换的主体；「知识库内容」以参考站卡片流当作中栏**默认首屏**；RSS/天气/日历等面板可同时作为右栏 widget 复用来丰富门户。

## 5. 布局改造需求

### 5.1 顶栏 Header
- 左侧：Logo + 站名「i-kit 控制台」→ 可预留「i-kit」品牌位 + 标语位。
- 中间：快捷功能入口（原有功能插件可平铺，或以「更多」收敛）——对应参考站的外链快捷入口位。
- 全局搜索框（占位「搜索（Ctrl + K）」）：回车弹出/聚焦后触发**知识库检索**，命中卡片流。
- 极右：**头像**（登录后显示头像+用户名缩略，点击弹出登录/账号菜单）→ 点击弹出**登录弹框**；未登录时为占位头像（也点开登录框）。暗色切换按钮保留。
- 移除原来顶栏直接堆叠的「system/manager/store/users」管理按钮（已收敛为「管理」分组，且仅在 admin 显示）。

### 5.2 左侧导航栏（桌面）
- 顶部：博主/站主签名 moto 位（可放一句话或站主昵称）。
- 分类/功能树：
  - 「知识库」展开 = 知识分类树（`CategoryTree`），点击分类 → 中栏按分类过滤卡片流。
  - 功能插件（Agent / 数据统计 / 便签 / 日历 / 待办 / 天气 / RSS / MD 剪贴板 …）作为同级导航项。
  - 「专栏/专题」：把部分内容策划成专题合集（可选，二期）。
- 「页面」组：归档库、关于我、留言板（见功能新增）。
- 站主专用（仅 admin）：系统 / 插件管理 / 插件商店 / 用户管理，位于底部，与普通功能**明显分隔**。

### 5.3 主内容区
- **默认首屏**：知识卡片流（复用参考站卡片：封面图 + 标题压图 + 摘要 + 作者/时间/浏览/标签/分类 + 分页）。
- 其它 tab：保留现有功能面板（Agent 对话流、统计信息、便签、日历、待办、天气、RSS、MD 剪贴板）。
- 顶部保留面包屑/当前分类标题 + 排序（最新/最热）+ 搜索过滤状态。

### 5.4 右侧 widget 栏（桌面）
- 热门文章（按浏览量/评分排序，点击定位卡片）
- 最新评论（知识库条目最新评分/评论）
- 标签云
- 动态日历（近 N 月有更新的日期高亮）
- 统计图表：分类雷达图 / 发布柱状图 / 近 10 月发布-评论趋势

### 5.5 响应式
- ≤768px：左右栏收起为抽屉/底部 Tab，主内容单列（保留现有底部 Tab 逻辑，但按新导航分组）。

## 7. 登录与账号调整

- **入口**：点击顶栏**头像** → 弹出登录框（复用 `AuthPanel` 视觉，改成弹窗而非整页/整栏）。
- **注册**：AuthPanel **隐藏注册 tab**，保留 登录 / 找回密码 两个入口。
- **新增用户方式**：站主登入后到「用户管理」→「添加用户」，填 用户名/密码/昵称/角色 → 由后端创建。后端 `register` 接口可保留但前端不暴露；或后端加 `adminCreateUser` 受 `requireAdmin` 保护。
- **登录态呈现**：头像 + 用户名 + 角色徽标；下拉菜单含「退出登录」。

- 系统监控、用户管理（角色/重置/禁用）、数据统计。
- 便签 / 日历 / 待办 / 天气 / RSS / MD 剪贴板功能面板。
- 暗色模式、三端（Web / Tauri / Capacitor）兼容。

## 10. 数据与接口影响

- 知识库：增加/复用 **浏览计数** 字段与接口（`GET /api/knowledge/:id` +1 浏览，或独立 `POST /api/knowledge/:id/view`）。
- 统计 widget：复用 `/api/plugins-data/statistics`；若需分类雷达/发布柱状，扩展该统计接口返回分类分布与按月发布数。
- 用户：新增 `adminCreateUser` 受 `requireAdmin` 保护；前端隐藏 register。
- 布局数据：站点 moto / 站名 / 关于我 文案 → 站点配置项（可在系统设置中维护，或抽 `config` 服务）。
- 评论：知识库评分/评论与插件商店评论复用现有能力。

## 11. 实施阶段建议

1. **阶段一优先**：先落地三栏骨架 + 卡片流 + 头像登录 + 屏蔽注册 + 手动加用户。
2. 每阶段完成即：`pnpm --filter @ikit/web build` + `tsc --noEmit` + 后端接口冒烟，再进入下一阶段。
3. 布局组件化：新增 `PortalLayout`（三栏）、`NavTree`（左栏）、`Widget*`（右栏）、`ContentCardFeed`（中栏卡片流）；复用现有 `*Panel` 组件。
4. 完成后按 AGENTS.md 不自动提交/部署，等待用户确认。

## 12. 验收标准（阶段一）

- [ ] 桌面三栏门户布局生效（左导航/中卡片流/右 widget），窄屏退化为单列+底部 Tab。
- [ ] 顶栏含 Logo/站名、快捷入口、全局搜索、头像（点击弹登录框）、暗色切换。
- [ ] 头像未登录占位 + 登录后显示用户信息；点击均弹出登录框。
- [ ] AuthPanel 无注册入口（仅登录/找回）。
- [ ] 站主可在用户管理添加用户（用户名/密码/角色/昵称）。
- [ ] 知识库首屏为卡片流：封面图+标题压图+摘要+作者/时间/浏览/标签/分类+分页。
- [ ] 既有功能插件（Agent/统计/便签/日历/待办/天气/RSS/MD）经左栏仍可进入。
- [ ] 站主管理（系统/插件/商店/用户）仅 admin 可见且与前台功能分隔。
- [ ] 构建 + 类型检查通过；后端接口冒烟通过（登录、用户新增、知识检索、统计）。

## 13. 风险与注意事项

1. **既有功能不可回归**：改造是「换壳」，功能面板逻辑尽量不动，只调容器与路由。
2. **卡片流数据**：知识库条目未必都有封面图 → 需提供默认占位/渐变色封面。
3. **widget 复用**：日历 widget 可复用商店日历插件的视图组件；避免与主面板重复实现。
4. **三端一致性**：Tauri/Capacitor 下的响应式需一并验证（窄屏抽屉/底部 Tab）。
5. **站主隔离**：任何 new admin 功能都要 `requireAdmin`，前端仅在 admin 渲染。
6. **权限**：屏蔽注册后，新用户只能由站主创建，注意默认角色与密码策略。

## 14. 实施完成记录（截至当前版本）

> 本文档对应的实现已落地，与本项目既有功能兼容。以下为实施完成情况（与第 2/4/6 节对应）。

## 18. 缺陷修复：Vditor 异步初始化时序（2026-10-15，与文章互链同批）

> 现象（用户实测）：进入文档编辑态提示「**编辑器加载失败 · Cannot read properties of undefined (reading 'currentMode')**」，随后降级为纯 Markdown textarea（看起来「不是可视化编辑」）。

- **根因**：Vditor 的 `new Vditor(...)` 是**异步初始化**——构造返回时 `this.vditor` 尚未赋值（`vditor/dist/index.js:16243` 的 `this.vditor = {...}` 位于 lute 脚本加载后的 `.then()` 内，`options.after` 在 `initUI()` 之后才被调用，`:16296`），而实例方法（`getValue/setValue/insertValue/focus/isUploading/setTheme`）内部都会读 `this.vditor.currentMode`（`getCurrentMode()`）。`VditorEditor.vue` 原先在构造后**立即**调用 `instance.setValue(props.value)` → 抛 `currentMode` 未定义 → 被 `catch` 判为「编辑器加载失败」并降级。
- **修复**（`apps/web/src/components/VditorEditor.vue`）：引入 `ready` 标志，**`after` 回调之前绝不调用任何实例方法**；初始内容与早期 `setValue` 排队到 `pendingValue`，在 `after` 中应用后再 `emit('ready')`；`readValue()` 在未就绪时返回 `pendingValue ?? props.value ?? ''`（**不返回空串**，避免自动保存基线错误把正文存空）；`focus()` / `isUploading()` / `insertValue()` 均加就绪守卫；`setTheme` 的 `watch` 增加 `!ready` 短路；`destroy()` 重置 `ready`/`instance`；新增 15s **就绪超时兜底**（lute 资源加载失败时 `after` 永不触发 → 降级到 textarea 并通知「已就绪」，避免永远停在「加载中」）；`retry()` 先取回当前内容再重建（重载不丢输入）。
- **验证**：真实浏览器（Edge headless + CDP）47 项端到端含「进入编辑态不降级 / 无 `currentMode` 报错 / 初始内容一致」；另用真实 Vditor 运行时做微测复现根因（构造后立即 `setValue` 抛 `currentMode` 未定义；排队到 `after` 后写入成功）。

- **真正的「按住拖拽把块拖到别处」未实现**：Vditor 无公开块拖拽 API；硬搬 Lute 渲染出的 DOM（`data-marker` / `data-block` / `<wbr>` 光标协议）风险高于收益。位置调整用块菜单的**「上移 / 下移」**等价完成（已实现并用真实浏览器验证）。
- 斜杠菜单**不复用** Vditor `hint`：`hint` 的语义是「把候选 value 插到光标处」，而斜杠命令要「先删除 `/xxx` 再插入新块」，两者行为不同；复用会污染 `[[` 补全的候选来源。
- `- ` / `> ` 等行内快捷是**自建补齐**（不是 Vditor 能力），已在代码注释中标注其在 Vditor 源码中的对应判断位置，便于后续升级时复核。

### 19.4 修复：行内格式「取消」时的 DOM ↔ Markdown 不一致

- **现象**：对已加粗的文字再次加粗（取消加粗）时，浏览器 `execCommand('bold')` 产出的是 `<span data-marker="**">`（**不是** `<strong>`）；Lute 不把无标记的 `<span>` 当加粗 → **DOM 已取消加粗、Markdown 仍是加粗**，保存后内容回退。
- **修复**：`lib/editorBridge.ts` 的 `normalizeInlineFormats()` 按**计算样式**把无标记的行内包裹元素改写成 Lute 认得的标签 + `data-marker`（`font-weight ≥ 600` → `strong[**]`、italic → `em[*]`、line-through → `s[~~]`、等宽 → `code[\`]`），随后派发一次 `input` 让 Vditor 重渲染该块并刷新撤销栈。悬浮格式条的加粗 / 斜体 / 删除线 / 行内代码四个动作都会走这一步。

## 20. 详情页无模式编辑（2026-10-16，完善⑧）——「始终可编辑 + 点外部收起」

> 需求原文（用户澄清）：**不单独出现「编辑页」**——站主打开详情时正文**始终**可直接编辑（点哪改哪，飞书 / Notion 式），焦点离开文档区即 flush 自动保存并**收起编辑外壳**（正文仍完整呈现）；再点任意处即可继续编辑；游客 / 非站主仍只读。

### 20.1 交互模型（不变式）

| 项 | 约定 |
|---|---|
| 站主进入详情 | 正文**直接可编辑**（无「✎ 编辑」按钮、无视图切换、无弹窗）；编辑器**常驻挂载** |
| 编辑外壳 | Vditor 工具栏 + 底部状态条 + 字段控件外观；**焦点在文档内**（或点容器内任意处）→ 展开；**点文档区外 / `Esc`** → 收起 + `flush()` |
| 进入详情 ≠ 开始编辑 | 只聚焦 / 只点击不输入 **不产生任何 PATCH**（沿用 `lib/autosave.ts` 的 unchanged 指纹短路） |
| 零布局跳动 | 两态下容器 / 正文的**宽高、内边距、相对偏移完全一致**（收起时按实测工具栏高度占位 + 底栏定高槽） |
| 不重挂载 | 外壳显隐只改 class / `display`，**不重建 Vditor**（内容与光标历史不丢）；仅「打开 / 切换文章 / 新建」时换实例 |
| 字段 | 标题 / 分类 / 标签 / 封面输入框恒在流内，非聚焦 / 非悬停 = **静态文本**外观（透明边框 + 透明底色），悬停 / 聚焦 / 外壳展开 = 出现输入控件外观 |
| 非站主 | 完全不变：`ArticleDetail.vue` 只读渲染，无编辑控件、无写请求 |

### 20.2 实现要点（`apps/web`）

- **单容器**：`ArticleEditView.vue` 重写为**站主侧详情文档容器**（`.article-doc`）；`App.vue` 的 `detailMode` 收敛为 `'list' | 'read' | 'new'`（**没有 `edit` 态**），站主渲染条件 `inEditMode = admin && (article || detailMode === 'new')`；`:key="editKey"` 只在「打开 / 切换文章 / 新建 / 重新载入」时自增。`ArticleDetail.vue` 保持零改动（仅服务非站主）。
- **外壳展开判据**：容器内 `pointerdown`（`document` 捕获，`onDocPointerDown`）或容器内 `focusin`。**必须用 pointerdown 而不能只靠 focusin**——`Esc` 收起外壳后焦点仍在正文里，再点正文不会触发 `focusin`，外壳将收不回来。
- **外壳收起判据**：容器外 `pointerdown`（同一处理器按 `contains(target)` 判定）或 `Esc`。`focusout` 只认「焦点移交给容器外**可聚焦元素**」（`relatedTarget === null` **不**收起：Vditor 重渲染会整体替换 `pre.vditor-reset`，焦点会瞬时掉到 `body`，据此收起会误伤块操作 / 斜杠菜单 / 撤销重做）。收起即 `autosaver.flush()`（未变更 → 指纹短路，不发请求）。
- **`Esc` 的挂载位置**：`document` 捕获阶段（**不是**容器）——Vditor 重渲染替换元素后焦点掉到 `body`，键事件不再经过容器，挂在容器上会「失联」；挂在 document 捕获还能保证在自建 / 内建浮层之前读到「浮层仍开着」的初始状态：浮层开着 → 放行让浮层自己关（第二次 `Esc` 收起外壳）。
- **零跳动的做法**：收起时给 `:deep(.md-editor)` 补 `padding-top: var(--ikit-toolbar-h)`，`--ikit-toolbar-h` = `VditorEditor` 暴露的 `toolbarElement()` **实测高度**（`is-measuring` 借一帧显示工具栏量取、同一任务内复位，不产生可见闪烁；窗口 resize 防抖重量）；底栏 `.ad-foot` 定高 30px，`v-show` 只收内部内容。实测（1280×900）：收起 / 展开两态容器均 `648 × 1295.9`、正文均 `640 × 915.1`、正文相对容器 `dx=4 / dy=314.8`、内边距均 `35px`。
- **编辑器内互链**：`VditorEditor.vue` 新增 `linkClick` 属性 → Vditor `options.link.click`（wysiwyg 下 Vditor 会 `preventDefault` 并回调）交回宿主：内部文档链接 → 同页跳转（同名多篇选择列表 / 失效提示与阅读端一致）、页内锚点 → 容器内滚动（精确 id → `heading-N` 同序 → 标题文本），外链 → `window.open(_blank)`。失效互链在编辑器内**只加 class**（不写 `title` / `data-*`：Lute 的 DOM→Markdown 会把 `<a title>` 变成 `[文字](url "title")`，等于改写用户内容）。`[[标题]]` 在编辑器内是**纯文本**（Lute 不渲染成 `<a>`），故约定 **`Ctrl/Cmd` + 点击** 跳转（容器捕获阶段 `click` + `caretRangeFromPoint` 命中 `[[…]]` 字符区间）；`[文字](ikit://doc/<id>)` 式单击即跳转。
- **关联调整**：`flushCurrent()` 改为「有容器实例即 flush」；`N` 快捷键在**外壳收起**时可用；`Ctrl/Cmd+S` 在详情打开时始终立即 flush；多端冲突提示条按**外壳是否展开**选口径（展开 = 「…你的修改仍在保存中 + 继续编辑」；收起 = 可「重新载入」，重载前先 flush 保住本端输入再重挂容器）；`onBeforeUnmount` 若仍脏则写 localStorage 快照兜底。

### 20.3 验证（真实浏览器，隔离实例）

- **真实浏览器（Edge headless + CDP，51 项全部通过）**：站主打开详情挂载常驻编辑器且不降级 / 无 `currentMode` 报错；打开详情 `PATCH = 0`；仅点击 + 聚焦不输入 `PATCH = 0`；输入后自动保存与 `Ctrl+S` 落库（内容为 Markdown 原文）；点外部 → 工具栏 / 状态条 `display:none`、编辑器**同一 DOM 节点未重挂载**、无多余 PATCH、两态几何完全一致；再次点击正文可继续编辑并落库；`Esc` 先关浮层再收外壳；标题 / 分类 / 标签 / 封面原位可改并落库；互链四类（wiki `Ctrl+点击`、id 式单击、页内锚点滚动、失效链接 toast + 虚线）与返回栈；`Markdown` 往返 16 类不丢格式 + 重载后 `Ctrl+S` 无 PATCH（幂等）；游客只读且零写请求、看不到草稿；新建在同一容器内首次输入即建草稿。运行期无未捕获异常。
- **已知等价归一化（非本次改动引入，不丢语义）**：Lute 的 DOM→Markdown 在首次保存时会做等价规范化——`- [x]` → `- [X]`、`> [!NOTE]` → `> [!NOTE] ✏️ Note`、表格单元格按列宽补空格；规范化后的形态是**不动点**（重载后 `Ctrl+S` 不产生 PATCH）。
- **构建**：`pnpm -r --if-present build` 通过（`apps/web` 含 `vue-tsc` 类型检查，exit 0）。
