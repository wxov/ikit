## 1. 目标与非目标

### 1.1 目标

1. **在详情页内完成全部编辑动作**：站主打开任一文章，点「✎ 编辑」即在同一内容区切换为编辑态（标题、正文、分类、标签、封面全部就地可改），**无任何弹窗**。
2. **新建文章=进入详情页草稿态**：左栏「✎ 新建文章」与目录树「＋ 新建子文档」都直接进入详情页的空白草稿编辑态；首次自动保存时创建真实条目（子文档保留 `parentId` 语义），全程无弹窗。
3. **Vditor IR 可视化编辑**：加粗/标题/列表/引用/代码块/表格/公式/图片/粘贴均有即时渲染；内容以 **Markdown 原文**落库，与阅读端 `markdown-it` 渲染保持同一份数据契约（不引入 HTML 存储）。
4. **自动存草稿 + 手动发布**：编辑过程自动保存（防抖 + 失焦/切页/离开前 flush + 失败重试 + 状态可见），「发布」把草稿转为已发布，「撤回」退回草稿；**草稿仅站主可见**（方案 X）。
5. **数据安全**：任何一次保存失败、刷新、断网、多端并发都不会静默丢内容；存量数据迁移有备份、幂等、可回滚、有验收证据。
6. **零阅读端回归**：游客的阅读体验、可见性隔离、评论、目录树、右侧栏、归档视图行为除「草稿不可见」这一项外完全不变。

### 1.2 非目标（本期不做）

- **不迁移阅读端渲染**到 Vditor/Lute：阅读继续 `markdown-it` + `markdown-it-katex` + `highlight.js` + 标题锚点（决策 5；同时规避 Vditor `method.min.js` 与 `index.min.js` **不可同时引入**的官方约束）。
- **不做版本历史 / 协同编辑 / 草稿公开分享链接 / 定时发布**。
- **不做 `'archived'` 的设置入口**：维持 2026-09 定稿的「归档 = 按年月浏览视图」语义（`docs/需求功能总览.md:132`），本期只在状态白名单里显式拒绝 `'archived'`。
- **不做编辑器内联评论 / 批注**（Vditor `comment` 仅 wysiwyg 支持，与 IR 冲突）。
- **不改移动端布局体系**（底部 Tab / 抽屉不动），只保证编辑态在 <768px 可用。
- **不做草稿的「预览为游客视角」独立页面**：用「返回阅读」按钮复用阅读态即可预览。
- **不引入 vue-router**：继续用 `App.vue` 的状态机（与现状一致，改动面最小）。

### 2.3 本次分析新发现（影响设计）

**F1（高）：`undefined`/`NULL` 的 `status` 必须视为「已发布」，否则存量文章会集体消失。**
SQLite 里 25 条、JSON 里 25 条 `status` 为空（历史上只有 `create` 写入 `'draft'`，其它路径从未写过 `status`）。若过滤谓词写成「严格等于 `'published'` 才可见」，这些条目对游客/低权限用户**立即不可见**。→ 过滤谓词必须为 `(e.status ?? 'published') === 'published'`（§4.6.1），迁移因此只需处理**显式 `'draft'`** 的 20 条。

**F2（高）：admin 的「读路径」多数没有带 `Authorization`。**
`resolveViewer` 从请求头解析（`routes.ts:86-119`）→ 无 token = guest。而以下 GET 均**未带 token**：
`App.vue:96`（categories）、`DocTree.vue:103`、`ContentCardFeed.vue:145`、`ArchiveView.vue:15`、`PortalRight.vue:32/:45/:57`、`CommentSection.vue:21`、`ContentCardFeed.vue:116`（view 计数）。
方案 X 落地后，**站主自己的左栏目录树 / 卡片流 / 归档 / 右栏会看不到草稿**（观感=「草稿丢了」）。→ 必须在这些调用点补 `headers: authHeaders()`（§5 清单逐条给出）。附带修正一个既有缺陷：admin 的分类树此前也是按 guest 过滤的（看不到 `private`/`groups` 文章的分类）。

**F3（高）：`KnowledgeEntryInput` 无 `status` → PATCH 无法发布/撤回，POST 无法创建非草稿。**
需扩展输入契约并收口默认值（`create`=draft、`importMany`=published、父容器可显式 published，见 §4.6.3 / §6.1）。

**F4（中）：空标题时首次自动保存会 400，破坏「首次保存即创建」。**
`routes.ts:533-535` 要求 title 与 content 同时非空；用户先粘贴正文再补标题是自然顺序。→ 放宽为「标题与正文不可同时为空」，空标题回落 `'未命名草稿'`；**发布时**再要求标题+正文非空（§4.5.3）。

**F5（中）：自动保存会持续触发 embedding 向量化。**
`service.ts:283-285`：只要 patch 带 `title`/`content` 且有 llm embedding 配置，每次保存都会调用一次 embedding 接口。2 秒一次自动保存 = 2 秒一次外部 API 调用 + 延迟。→ 自动保存路径显式跳过向量化，发布/手动保存时才向量化（§4.4.5）。

**F6（中）：草稿/私有父容器的可见子项在左栏目录树会变成「孤儿」。**
`DocTree.vue:60` `roots = visible.filter(e => !e.parentId)`：子项有 `parentId` 但父项不可见时，子项既不是根、也不会被任何父节点渲染 → 游客侧看不到（且这是**现存缺陷**：private 父 + public 子今天就复现）。导入路径还会放大它：`ImportDocsDialog` 新建的父容器经 `create()` 是 `draft`。→ 修 `roots`（孤儿提升为根，§4.6.4）+ 导入弹窗新建父容器显式 `status:'published'`。

**F7（低）：README 声称的编辑体验（分屏、草稿自动保存、`/`、`N`、`Ctrl+S`）与代码不符。**
`README.md:177` vs `App.vue:380-389`。本期把其中 `N`/`Ctrl+S`/自动保存/可视化编辑做实，`/` 搜索是否顺带补见 §10-Q7。

### 3.1 编辑器

|---|---|---|
| **Vditor 4.0.0（`mode:'ir'`）** | ✅ **推荐（已决策）** | 唯一同时满足「IR 即时渲染 + 输出 Markdown + 表格/公式/代码块/粘贴上传开箱可用 + 中文语境优化 + 无框架耦合」的成熟方案；懒加载后不进首屏；`detached` 型 API（`new Vditor(el, options)` + `getValue()/setValue()/destroy()`）与现有「无 router 的状态机组件」贴合 |

### 3.3 「首次保存创建」的时机与校验

| 方案 | 结论 | 理由 |
|---|---|---|
| **首次自动保存即 POST（放宽空标题）** | ✅ **推荐** | 满足决策「新建进详情页 → 首次自动保存即创建」；用户先写正文再补标题的路径不会 400；空标题回落 `'未命名草稿'`，目录树/卡片有可读标签；发布时再强制标题+正文非空 |

### 3.5 存量迁移方式

| 方案 | 结论 | 理由 |
|---|---|---|
| **服务启动时一次性幂等迁移（标记 + 截止时间 + 自动备份）** | ✅ **推荐** | 与部署流程零耦合（`update-server.ps1` / docker 重启即生效），不会「忘了执行脚本」；幂等标记与数据同库，备份与回滚可脚本化 |

#### 4.1.2 懒加载（`apps/web/src/lib/vditor.ts`，新增 ~90 行）

```ts
// 单例 Promise：整个会话只加载一次；CSS 与 JS 都进独立 chunk，不进首屏
let mod: Promise<{ default: typeof import('vditor').default }> | null = null
export function loadVditor() {
  mod ??= (async () => {
    await import('vditor/dist/index.css')          // Vite 会产出独立 CSS chunk，随动态 import 注入
    const m = await import('vditor')
    return { default: (m as any).default ?? m }
  })()
  return mod
}
export const VDITOR_CDN = '/vditor'                 // 见 4.1.3
export function vditorThemeOf(theme: 'light' | 'dark') {
  return theme === 'dark'
    ? { editor: 'dark', content: 'dark', code: 'github-dark' }
    : { editor: 'classic', content: 'light', code: 'github' }
}
```

要点：
- **只有进入编辑态才调用** `loadVditor()`；阅读态/游客永不下载 Vditor（首屏体积零变化）。
- `VditorEditor.vue` 里 `await loadVditor()` 后再 `new Vditor(...)`；组件卸载时 `vditor.destroy()` 并把宿主 `innerHTML` 清空（避免残留 DOM 与定时器）。
- 不做 `optimizeDeps.exclude`（Vditor 的 `main` 是 CJS/UMD，排除预打包会破坏 dev 的 ESM 互操作）；dev 首次预打包稍慢属一次性成本，故 **`vite.config.ts` 不改**。
- 失败降级：`loadVditor()` 抛错 → 编辑态显示「编辑器加载失败 · 点击重试」，并提供**纯 Markdown textarea 兜底**（复用同一 `v-model` 契约），保证断网/资源缺失时仍能编辑（AC-19）。

#### 4.1.5 图片上传 / 粘贴（`upload.handler`）

**源码级约束（§2.2-5/6）**：设了 `handler` 后 Vditor 不做内置校验、不自动插入、不解析我们的返回结构。因此：

```ts
async function uploadHandler(files: File[]): Promise<string | undefined> {
  const lines: string[] = []
  for (const f of files) {
    if (!f.type.startsWith('image/')) return '仅支持图片文件'
    if (f.size > 5 * 1024 * 1024) return `图片过大（最大 5MB）：${f.name}`
    try {
      const dataUrl = await readAsDataURL(f)                       // 复用 ArticleEditor.vue:39-44 的写法
      const r = await api<{ url: string }>('/api/upload', {
        method: 'POST', headers: authHeaders(),
        body: JSON.stringify({ name: f.name, data: dataUrl }),
      })
      lines.push(`![${f.name}](${r.url})`)
    } catch (e: any) { return `上传失败：${e.message}` }            // 返回字符串 = Vditor 弹提示
  }
  vditor.insertValue(lines.join('\n'))                             // 必须自己插入
  return undefined
}
```

- 覆盖三条路径：工具栏「上传」按钮、**剪贴板粘贴图片**、拖拽入编辑器（`fixBrowserBehavior.ts:1574-1576` 三处都进 `uploadFiles`）。
- 返回体仍是 `/uploads/<file>` 相对 URL，与现有封面/正文图片一致（**桌面/移动端 `VITE_API_BASE` 下相对路径的既有缺陷不在本期范围**，§10-Q6）。
- 不设 `linkToImgUrl`（会把站外 `http(s)` 图片转存到我们服务器，本期不做）。

#### 4.1.6 与阅读端渲染的一致性取舍（明确承认差异）

| 维度 | 编辑态（Vditor/Lute） | 阅读态（markdown-it） | 处置 |
|---|---|---|---|
| 代码高亮 | 自带 hljs 1.05 MB + 主题从 `cdn/js/highlight.js/styles/*` 动态加载 | `highlight.js@11.12.0` 按需注册 20+ 语言 + 全局 `github-dark.css`（`markdown.ts:4`） | 两者都作用于 `.hljs`，**存在样式叠加**：编辑器内后加载的 Vditor 主题生效（可接受）；AC-15 要求明暗两态目视核对 |
| 数学公式 | Vditor 自带 KaTeX（版本随 4.0.0） | `katex@0.18.4` + `markdown-it-katex`（`markdown.ts:79`） | 极端语法边缘可能有排版差异；**数据是同一份 Markdown**，不改 |
| 原始 HTML | `preview.markdown.sanitize:true`，允许部分 HTML | `html:false`（`markdown.ts:61`）→ 原文转义显示 | **差异最大项**；约定「正文不写原始 HTML」（文档同步写明）；AC-16 用含 `<div>` 的样本核对 |
| 标题锚点 | 无（`toc:false`） | 生成 `heading-N` 锚点（`markdown.ts:94-101`） | 阅读端不变 |
| 表格/任务列表/脚注 | Lute 完整支持 | GFM 表格支持（markdown-it 默认），任务列表/脚注**不渲染成样式** | 编辑器内更"好看"；若要求一致，可在阅读端补 `markdown-it-task-lists`（**本期不做**，仅记录） |
| Emoji | 图片/字符混排（`emojiPath` 本地） | 原样字符 | 可接受 |
| 流程图/图表 | **不支持**（未拷 mermaid/echarts 资源） | 不支持 | 一致：本期均不支持，文档写明 |

**结论**：编辑态渲染与阅读态渲染**不追求像素级一致**，只保证「同一份 Markdown + 阅读端渲染结果不回归」。AC 用「保存后切到阅读态目视」来验收，而不是比两套引擎的 DOM。

#### 4.1.7 CSS 隔离与主题

- **实测结论（§2.2-4）**：Vditor `dist/index.css` 413 个选择器**全部**带 `vditor` 前缀 → 引入它不会污染门户（无需 Shadow DOM / iframe）。

### 4.4 自动保存控制器（`apps/web/src/lib/autosave.ts`）

#### 4.4.1 状态机

```
idle ──input──▶ dirty ──(debounce 2s / maxWait 10s / flush 触发)──▶ saving
                  ▲                                                   │
                  │                                     ┌─────────────┴─────────────┐
                  │                                  200 OK                      失败(5xx/网络)
                  │                                     │                             │
                  └──────── input ──────── saved ◀──────┘                      退避重试(1s/2s/5s/10s)
                                                                                      │
                                                                         超过 maxRetries → error(可点重试)
```

| 参数 | 值 | 说明 |
|---|---|---|
| `delay`（防抖） | **2000 ms** | 决策建议 1.5–2s；取 2s 兼顾「打字时不频繁写库」与 SQLite 全量重写（`store.ts:139-188`）成本 |
| `maxWait` | **10000 ms** | 连续打字不停也保证每 10s 落一次盘 |
| `maxRetries` | 4（退避 1/2/5/10s） | 5xx 与网络错误重试；**4xx 不重试**（校验类，立即显示错误） |
| 串行化 | 全程只允许一个 in-flight 请求 | 杜绝乱序覆盖（旧请求后到把新内容写回） |
| `rev` | 单调递增序号 | 响应回来时若 `rev < latestRev` → 只更新 `lastSavedAt`，**不回写编辑器**（避免把旧内容灌回正文） |
| unchanged 短路 | `isEqual(snap, lastSavedSnap)` → 不发请求 | 打字删除回原样 / 失焦 flush 时不做无意义写库 |

#### 4.4.2 flush 触发点（全清单）

| 触发 | 位置 | 说明 |
|---|---|---|
| 防抖到期 / maxWait | 控制器内部 | 主路径 |
| Vditor `blur` | `VditorEditor.vue` `options.blur` | 失焦即存（决策 4） |
| 分类/标签/封面/标题变更 | `ArticleEditView` 各 `@change/@blur` | 与正文同一控制器（任意字段变更都 `schedule()`） |
| `Ctrl/Cmd+S` | `App.vue:onKeyShortcut`（新增分支） | 编辑态 → `preventDefault()` + `flush()`；非编辑态不拦截（避免吃掉浏览器保存） |
| `document.visibilitychange → hidden` | `ArticleEditView` `onMounted` 注册 | 切标签页/最小化立即存 |
| `window.beforeunload` | 同上 | 若仍 dirty：**同步写 localStorage 快照** + `event.preventDefault()` 触发浏览器自带确认（**不是自定义弹窗**） |
| 离开编辑态（返回阅读/取消/跳转其它文章） | `App.vue` 跳转编排 | `await flush()`；失败则留在编辑态 |
| 点「发布/撤回」 | `ArticleEditView` | **先 flush 再改 status**（保证发布的就是最新正文） |
| 删除前 | `ArticleEditView` | 无（删除即丢弃，由 `confirm()` 兜底） |

#### 4.4.3 保存请求形态

```ts
// 首次（虚拟草稿）
POST /api/knowledge/entries
{ title, content, category?, tags, cover?, parentId?, status: 'draft' }

// 后续（自动保存；autosave:true 表示跳过向量化，见 4.4.5）
PATCH /api/knowledge/entries/:id
{ title, content, category, tags, cover, autosave: true }

// 发布 / 撤回（不带 autosave → 触发向量化）
PATCH /api/knowledge/entries/:id
{ title, content, category, tags, cover, status: 'published' | 'draft' }
```

- **每次提交全字段**（不用 diff patch）：`update()` 对 `category/cover` 有「显式传空 = 清空」的语义（`service.ts:253-258`、`:278`），全字段提交可以避免「想清空却清不掉」的歧义。
- **标题为空时不发 `title` 字段**（配合 F4 的服务端「空标题保留原值」语义），避免把已有标题清成空串。

#### 4.4.4 本地快照（`apps/web/src/lib/draftSnapshot.ts`）

- Key：`ikit-kb-snap:<entryId>`（已有条目）与 `ikit-kb-snap:new:<parentId || 'root'>`（虚拟草稿）。
- 写入时机：每次 `input`（节流 500ms 写一次，避免每键 `JSON.stringify` 大文档）+ `beforeunload` 同步写 + 保存失败时写。
- 清除时机：保存成功（200）后清除对应 key。
- 读取时机：进入 `new` 态（提示恢复）与进入 `edit` 态时若 `snap.updatedAt > entry.updatedAt`（提示「有比服务端更新的本地内容」）。
- **与 Vditor 内建 cache 的关系**：`cache.enable:false`（§4.1.4）——内建 cache 会自动用 localStorage 覆盖传入的 `value` 且只弹一个 tip，行为不可控；改由我们自己的快照 + 显式提示条接管（**单一事实源**）。

#### 4.4.5 跳过 embedding（F5）

- 路由层：`PATCH` 把 `body.autosave === true` 映射为 `ctx.knowledge.update(id, patch, { skipEmbedding: true })`。
- 服务层：`update(id, patch, opts)` 中 `if (embed && !opts?.skipEmbedding && (patch.title || patch.content)) await vectorize(entry)`（改 `service.ts:283-285`）。
- 结果：自动保存期间零 embedding 调用；**发布/撤回与手动保存不跳过** → 检索质量不受影响；`Agent knowledge_search` 的向量召回在发布后即可用。

#### 4.4.6 性能红线

| 红线 | 原因 |
|---|---|
| 禁止在 `input` 回调里 `vditor.getValue()` | 每次按键做一次完整 Markdown 序列化（O(n)），大文档明显掉帧；改为「保存时读一次」 |
| 禁止每次按键 `JSON.stringify` 整个快照 | 快照写入节流 500ms |
| 禁止并发 PATCH | 串行化控制器 |
| 不做 `dataKey++`（编辑中不重挂载列表） | 避免打字时左栏/右栏/卡片流反复重建（也是 §9-R8 的缓解） |

### 4.5 发布 / 撤回 / 删除

#### 4.5.1 契约

| 动作 | 请求 | 前置校验 | 结果 |
|---|---|---|---|
| 发布 | `PATCH /:id { status:'published', ...全字段 }` | 标题、正文均非空（客户端内联提示 + 服务端 400 兜底） | `article.status='published'`，游客立即可见（刷新后） |
| 撤回 | `PATCH /:id { status:'draft', ...全字段 }` | 无 | `article.status='draft'`，非 admin 立即不可见（新请求起效） |
| 归档 | — | — | **不提供入口**；`status:'archived'` 在路由层被 400 拒绝（§6.2） |
| 删除 | `DELETE /:id`（既有，`routes.ts:673-680`） | 站主 + `confirm()` | 软删除进回收站 |

#### 4.5.2 发布前后置

- 前置：`await flush()` 成功（否则中止并提示）。
- 后置：`emit('status', entry)` → App `dataKey++ / docTreeKey++`（卡片流/目录树/右栏一致刷新）；顶部内联 toast「已发布 · 游客现已可见」/「已撤回 · 仅站主可见」（**非弹窗**，3s 自动消失）。
- **发布后停留在编辑态**（用户按「返回阅读」查看最终效果）——备选方案「发布即切回阅读」列入 §10-Q1。

#### 4.5.3 校验规则（服务端权威）

| 场景 | 规则 |
|---|---|
| `POST` 创建（草稿流） | `title` 与 `content` **不可同时为空**；`title` 空 → 回落 `'未命名草稿'`；`status` 仅接受 `'draft'\|'published'`（缺省 `'draft'`） |
| `PATCH` 自动保存 | `title` 为空 → 保留原值；其余字段全量覆盖 |
| `PATCH` 发布 | 合并后最终结果的 `title` 与 `content` 均非空，否则 400 `发布前需填写标题与正文` |
| `PATCH` status 值 | 白名单 `'draft'\|'published'`；`'archived'` 或其它 → 400 |

- **开关**：`draftVisibility: 'admin-only'（默认） | 'everyone'`（Config + env `KB_DRAFT_VISIBILITY`，env 优先，范式照 `plugin-registry/src/index.ts:43-46`）。`'everyone'` = 完全等价现状（零过滤），用于一句话回滚。

#### 4.6.2 方案 X vs 方案 Y（对比与推荐）

| 维度 | **方案 X：草稿仅站主可见（推荐，已拍板）** | 方案 Y：草稿仍全员可见 + 徽标 |

### 4.7 存量历史数据迁移（用户已确认：一次性迁移为 published）

#### 4.7.1 目标与范围

| 项 | 设计 |
|---|---|
| 迁移范围 | **仅** `status === 'draft'` 且 `createdAt < MIGRATED_DRAFT_CUTOFF` 的**未删除**条目 → `'published'` |
| 不迁移 | `status` 为空的条目（F1：视为已发布，无需改）、`'published'`、`'archived'`、`deletedAt` 非空（回收站，恢复后由用户自行处理） |
| 截止时间常量 | `const DRAFT_PUBLISH_CUTOFF = '2026-10-20T00:00:00.000Z'`（写入 `migrate.ts`，含义 = **本功能上线前**）；改动此常量视为数据迁移变更，需评审（防止误伤新流程产生的真实草稿） |
| 幂等标记 | `db.meta.draftPublishV1 = <ISO 时间>`（与数据同库，随备份/回滚一起走） |
| 自动备份 | 写入前复制存储文件到同目录 `knowledge.db.bak-<yyyyMMddHHmmss>`（JSON 同理 `knowledge.json.bak-<ts>`），日志打印绝对路径；失败则**中止迁移**（不冒险改数据） |
| 执行位置 | `packages/plugins/knowledge/src/index.ts` `apply()` 内、`createKnowledgeService()` **之前**（`index.ts:69` 前）：`await migrateLegacyDrafts(store, { cutoff: DRAFT_PUBLISH_CUTOFF, enabled })` |
| 一次性 | 标记存在 → 直接 return（**不查不强改数据**，启动开销 = 一次 meta 读） |
| 开关 | `KB_MIGRATE_DRAFT_STATUS=off`（或 Config `migrateDrafts:'off'`）→ 跳过（仍写标记？**不写**，便于日后手动开启） |
| 日志 | `[knowledge] draft-publish migration: drafts=20 published=20 skipped=0 backup=/abs/path/knowledge.db.bak-20261020T101500 v1`（一行，便于 grep 与验收） |

#### 4.7.2 为什么选「启动幂等迁移」而不是「独立脚本」

1. **不会漏执行**：`update-server.ps1` / docker 重建重启即生效，无需人工多一步；生产无人守着执行脚本。
2. **可审计**：标记与数据同库 → 备份文件里同时含数据与标记，回滚后状态自洽（不会出现「数据回滚了但标记还在 → 永不重跑」或反之）。
3. **幂等 + 截止时间双护栏**：即使标记文件/键丢失导致重跑，`createdAt < cutoff` 保证**永远不会把上线后新建的真实草稿发布出去**。
4. 独立脚本仍可**同时提供**（`scripts/migrate-draft-status.mjs --dry-run/--apply`，复用同一 `migrate.ts`），用于「迁移前预演」与极端情况手动重跑 —— 但**不作为唯一路径**。

#### 4.7.3 JSON / SQLite 双存储兼容

| 存储 | `meta` 承载 | 迁移实现 | 注意 |
|---|---|---|---|
| **SQLite（生产现状，`.env.example:14`）** | 新增表 `meta(key TEXT PRIMARY KEY, value TEXT)` | `store.ts` 建表（`:46-78` 的 `db.exec` 内追加）+ `load()`（`:95-133`）读入 `db.meta` + `persist()`（`:139-188`）`DELETE FROM meta` + 重插 | `persist()` 是全量重写，meta 一并原子提交（BEGIN/COMMIT 已有） |

| JSON→SQLite 自动迁移（`index.ts:83-100`） | 透传 `meta` | `migrateFromJson` 增加 `meta: data.meta ?? {}` | **否则「JSON 迁移过 + SQLite 空库」的实例会在切换存储后重跑迁移**（截止时间护栏仍在，但会多一次无谓写） |

### 4.8 WS 回声抑制与多端联动

**现状（§2.1-15）**：`knowledge:changed` 只进 `App.vue:41` 的 `events` 数组供 `SystemPanel` 展示，**没有任何列表重载逻辑** → 当前不存在回声风险。

**因此本期的设计原则是「不引入回声」而不是「事后抑制」**：

| 规则 | 设计 |
|---|---|
| 编辑态**永不**因 WS 自动重载 | 编辑期间忽略所有 `knowledge:changed`（含自己触发的 2s 一次广播）→ 从根上不可能覆盖正在打字的内容 |
| 保存的**唯一事实源**是 HTTP 响应 | `PATCH/POST` 返回的 `entry` 才用于更新本地 `article`（`rev` 校验），不用 WS 推断 |
| 他端修改 → **提示条而非覆盖** | 若编辑态收到 `payload.action==='update'/'remove'` 且 `payload.entry.id === 当前 id` 且**不是**自己的保存（自更新识别：记录自己最后一次保存的 `updatedAt`，相等即忽略）→ 顶部黄条「该文章已在其它端被修改 · 重新载入」（用户显式选择才 `setValue`） |
| 阅读态 | 保持现状（不自动刷新）→ 与「手动刷新/重挂载」一致，避免本期引入全站重载风暴；将来若要实时，按同样的「编辑态豁免」规则扩展 |
| 多端可见性一致性 | 发布/撤回后其它端**只有重新拉取列表才看到状态变化**（可接受；AC-24 用两个浏览器窗口验证：编辑端输入不被覆盖 + 另一端刷新后状态正确） |

> **第 2 轮复验收尾（R2-2 / R2-3 / R2-4，2026-10-13）**：上表「提示条」一行的口径按用户决定收敛——**仅站主（admin）提示**（游客 / 登录非站主不弹条）；**同一 `updatedAt` 只提示一次**（按文章 id 记录最近提示过的版本，值相同的重复广播不再弹、出现新的 `updatedAt` 才再提示；切换文章 / 离开详情 / 删除时重置该记录，用户点「继续编辑」/「×」收起时**保留**）；`remove` 分支已落地（他端软删除 → 阅读态「返回列表」、编辑 / 新建态「返回列表 / 继续编辑」）。实现与实测证据见文末「实施记录 → 第 2 轮复验收尾（R2 收尾修正）」。

### 6.2 HTTP

| 接口 | 变化 | 兼容性 |

## 8. 验收标准（可操作 AC）

> 约定：所有 AC 需在 **develop 分支本地 `pnpm dev` + `pnpm dev:web`** 上手工执行并留证据（截图/命令输出）；`游客`= 无 token 的隐身窗口；`站主`= admin 登录窗口。

### A. Vditor 集成本身

- **AC-2 离线资源**：断开外网（或 hosts 屏蔽 `unpkg.com`）后进入编辑态 → 工具栏图标、中文提示、代码高亮主题、内容主题、`$公式$` 渲染**全部正常**；Console 无 `unpkg.com` 请求、无 404。
- **AC-3 IR 编辑能力**：在编辑区依次验证：`**加粗**`、`# 标题`、`- 列表`/`1. 列表`/`- [ ] 任务`、`> 引用`、```` ```js ```` 代码块（有高亮）、GFM 表格（3×3）、行内 `$a^2+b^2=c^2$` 与块级 `$$…$$`、`![图](/uploads/x.png)`、从外部网页**粘贴含图片与格式的内容**（图片走 `/api/upload` 并插入 `/uploads/...`，不出现 `data:` base64 内联）。

### B. 就地编辑 / 新建 / 自动保存 / 发布

- **AC-6 就地编辑无弹窗**：站主在详情页点「✎ 编辑」→ **不出现任何遮罩/弹窗**；标题/正文/分类/标签/封面都可在内容区直接改并生效。
- **AC-7 新建进详情页**：左栏「✎ 新建文章」→ 内容区直接变为**空白草稿编辑态**（无弹窗）；目录树某节点的「＋ 新建子文档」→ 同样进入空白编辑态，且保存后该条目出现在该节点的子级（`parentId` 正确）。
- **AC-8 首次保存即创建**：在空白新建态**先只粘贴正文（标题留空）**等待 ≥2s → Network 出现 `POST /api/knowledge/entries`（201，`status:'draft'`）→ 左栏目录树出现「未命名草稿」；随后输入标题 → 变为 `PATCH /:id`。
- **AC-9 自动保存节奏**：连续输入 10s → PATCH 次数 ≤ 6（防抖 2s + maxWait 10s）；停止输入 2s 内出现一次 PATCH；切换浏览器标签页 → 立即 PATCH（`visibilitychange`）。
- **AC-10 保存状态指示**：编辑时状态条依次呈现 `未保存 → 保存中… → 已保存 HH:MM`；人为断网后输入 → 显示 `保存失败 · 点击重试`，恢复网络后 9s 内自动重试成功并回到「已保存」。
- **AC-11 退出不丢内容**：输入后立即点「← 返回阅读」→ 先看到「保存中…」再切到阅读态，阅读态内容为最新（等于输入内容）；点「取消」时若已脏 → 按钮变「确认放弃未保存修改？」；再点一次 → 内容回滚到最近一次保存的版本。
- **AC-12 刷新/崩溃不丢**：编辑态输入后（未等自动保存）直接 F5 刷新 → 重新进入该文章编辑态时出现**非弹窗提示条**「检测到未保存的草稿 · 恢复 / 丢弃」；点恢复后内容完整。新建态（未创建）刷新同理（`ikit-kb-snap:new:*`）。
- **AC-13 Ctrl+S**：编辑态按 `Ctrl/Cmd+S` → 浏览器保存对话框**不出现**，且立即触发一次 PATCH（观察 Network）。

- **AC-17 一致性抽查（两引擎差异符合预期）**：准备一篇含「标题/列表/引用/代码块/表格/公式/图片/原始 `<div>`」的样本；编辑态渲染 → 保存 → 阅读态渲染：加粗、标题、列表、引用、代码高亮、表格、公式、图片**均正常**；原始 HTML 在阅读态按转义文本显示（预期差异，已文档化）。

### C. 草稿语义 / 迁移 / 多端

- **AC-20 存量迁移正确性（含幂等与回滚演练）**：
  1. 迁移前只读查询记录基线（本地工作区 = `draft:20 / published:1 / NULL:25`，生产以实测为准）；
  2. 启动一次 → 日志出现 `draft-publish migration: drafts=<N> published=<N> ... backup=<path>`，且备份文件存在；
  3. 迁移后查询：`createdAt < cutoff` 的 `draft` 数 = 0，`published` 数 = 原值 + N；无状态条目数量不变；
  4. **再启动一次** → 日志无 migration 行（幂等）；
  5. 删除 `meta` 标记后重启（演练）→ 日志再次出现但 `drafts=0`（截止时间护栏）；
  6. 回滚演练：停服 → 还原备份文件 → `KB_DRAFT_VISIBILITY=everyone` 启动 → 可见性与迁移前完全一致。
- **AC-21 草稿对非 admin 不可见（三读路径）**：草稿存在时，隐身窗口 ① 列表接口/卡片流不含该条；② **`GET /api/knowledge/categories`** 不含该草稿独有分类；③ 直接访问该文章 URL/由卡片进入的详情**无入口**；④ 评论接口 `GET /:id/comments` 返回空而非评论内容。
- **AC-22 Agent 检索一致性**：以非 admin 账号经由 Agent 提问命中草稿标题 → 回答中**不出现**该草稿内容（`knowledge_search` 过滤生效）；admin 提问可命中。
- **AC-23 导入默认 published**：用左栏「📥 导入文档」导入 2 个 `.md`（含子目录分类）→ 导入完成即用**隐身窗口**刷新 → 两条均可见（无需手动发布）；用弹窗「＋新建父文档」创建容器后导入到其下 → 隐身窗口左栏目录树能看到容器与其子项（F6 修正生效）。
- **AC-24 多端不覆盖输入 + 状态联动**：窗口 A 编辑态持续输入；窗口 B（同账号）在同一秒发布/撤回同一文章 → **A 的输入内容不被覆盖**，A 顶部出现黄色提示条「该文章已在其它端被修改 · 重新载入」；点「重新载入」才替换内容。
- **AC-25 站主侧读路径补授权**：站主登录后左栏目录树 / 卡片流 / 归档 / 右栏 / 编辑器分类下拉**均含草稿与 `private` 分类**（对比修复前：这些位置看不到草稿）——证明 F2 的 7 处 `authHeaders` 生效。
- **AC-26 孤儿根节点修复**：构造「草稿/私有父 + public 子」→ 隐身窗口左栏目录树**能看到该子项**（作为根显示），不再消失。

### 12.2 实施顺序（能力先行 vs 语义先行）

**推荐：能力与语义「同一 release 上线、分阶段提交」，清理与文档收尾随后。** 理由：迁移的 `DRAFT_PUBLISH_CUTOFF` 必须等于「草稿语义上线时刻」，若两阶段跨 release，阶段 1 用新流程产生的真实草稿会在阶段 2 被迁移误发布（R10）。同 release 分提交既保留可分步验证的好处，又不产生时间窗歧义。

| 阶段 | 内容 | 可分步验证（提交内 AC） | 说明 |
|---|---|---|---|
| 1（能力） | 契约（`status` 支持 / POST 放宽 / `skipEmbedding`）+ Vditor 集成 + 详情页双态 + 新建虚拟草稿 + 自动保存 + 发布/撤回 | AC-1…AC-19、AC-24、AC-27 | 此时 `status` 尚未参与可见性 → **对现状零行为影响**，可独立验证；发布/撤回已能改状态 |
| 2（语义） | `isVisible` 过滤 + 开关 + 迁移（marker/截止/备份）+ 前端 7 处 `authHeaders` + 徽标 + F6 | AC-20…AC-23、AC-25、AC-26、AC-30 | 引入行为变化；**上线前先做只读数据核对 + 备份演练**；随时可 `KB_DRAFT_VISIBILITY=everyone` 回滚 |
| 3（清理/文档） | 删除 `ArticleEditor.vue` 与旧状态/样式；`N`/`Ctrl+S`/（可选）`/`；§11 全部文档同步；`vue-tsc` 接入（Q9） | AC-28、AC-29 | 死代码清零 + 文档-代码一致 |

> 若因故必须分批发布：把 `DRAFT_PUBLISH_CUTOFF` 设为**阶段 1 的发布日期**（语义 = 「本功能上线前创建的 draft 才视为历史遗留」），并在阶段 2 上线前重跑 §4.7.5 的核对命令；这是唯一被允许的分批方式。
