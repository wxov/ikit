> 版本：v1.0（已实施）

> 关联文档：《门户布局与功能改造需求文档.md》§14（现状总览，已同步更新）、《插件系统与权限管理体系扩展需求文档.md》（历史背景）

## 1. 背景与目标

### 1.1 现状（以代码为准）

| 项 | 现状 |
|---|---|
| 权限模型 | 仅 3 种固定角色：`guest`（未登录）/ `user`（注册）/ `admin`（站主）；**无用户组** |
| 用户 | `User.role: 'user'|'admin'`，存 `data/accounts.json`（`account` 插件） |
| 插件权限 | `PluginVisibility = { guest, user, admin }` 三个布尔，按角色开关（`plugin-registry`） |
| 文章权限 | **无可见性字段**；`GET /api/knowledge/entries` 对所有人返回全部文章，游客可看全部内容 |
| 目录「更多操作」 | 左栏 `DocTree` 的 `⋯` 菜单：新建子文档 / 移动到… / 编辑 / 置顶 / 删除（仅站主） |
| 系统面板 | `SystemPanel`（底部「系统」）：系统信息 / demo 测试 / 事件流，无批量权限 |
| 用户管理 | `UserManager`：添加 / 禁用 / 删除 / 角色调整，无用户组 |
| 目录层级 | `parentId` + `sortOrder`（父子关系已存在，是「父→子同步」的基础） |

### 1.2 目标

1. **文章级可见性**：按用户组控制单篇文章的可见范围。
2. **目录权限设置**：在目录「更多操作」中设置权限，父文件设置后按策略同步子文件。
3. **批量权限操作**：系统选项中树形列出所有文件，批量更改选中文档权限。
4. **用户组**：文档权限与插件权限统一按用户组设置；`guest`（游客）与 `admin`（站主）默认存在。

---

## 2. 已确认的设计决策（站主拍板）

1. **文章可见性**：四级快捷（公开 / 仅登录 / 指定组 / 仅站主），底层按组集合判定。
2. **用户组归属**：一个用户可属多个组，权限取并集。
3. **插件权限**：统一从「guest/user/admin 布尔」迁移为「用户组」模型。
4. **存量兼容**：已有文章默认公开，不回归。
5. **推进方式**：先落需求文档，再逐步实施。

---

## 3. 权限模型设计

### 3.1 用户组 Group

```ts
interface Group {
  id: string          // 内置组固定 'guest' | 'user' | 'admin'；自定义组为 UUID
  name: string        // 显示名
  builtin: boolean    // 内置组 true，不可删除
  description?: string
  parentId?: string   // 父组 id（包含关系：上级组包含下级组；仅自定义组可设，内置组恒为顶层）
  createdAt: string
}
```

**组的包含关系（上级组包含下级组）**：`Group.parentId` 指向父组，形成树状层级。用户在组 X 时，其有效组集合 = X ∪ X 的全部子孙组（递归展开、取并集）；因此**上级组成员自动获得下级组的文档/插件权限**。仅自定义组参与包含（内置组恒为顶层、不可作为父组/子组）；设置父组时校验「不能挂到自身或自身子孙下」；删除组时其子组上挂到被删组的父组。

**内置组（默认存在、不可删除）**：

| id | 名称 | 说明 |
|---|---|---|
| `guest` | 游客 | 未登录自动归属 |
| `user` | 注册用户 | 普通用户默认归属 |
| `admin` | 站主 | 最高权限，恒可见全部内容与插件 |

自定义组由站主增删改（如 会员 / 编辑 / VIP…）。

### 3.2 用户与组

- `User` 新增 `groupIds: string[]`（为空 = 默认归入 `['user']`）。
- `role='admin'` 的用户视为拥有全部权限（等价于所有组 + 管理权限）。
- **权限判定**：`resolveGroups(user) → Set<string>`：
  - 未登录 → `{ 'guest' }`
  - admin → 特殊标记（恒可访问全部）
  - 其他 → `user.groupIds`（为空时 `['user']`）

### 3.3 可见性判定（统一规则）

文章与插件均存「可见组集合」，判定规则一致：

```
canAccess(entry, user):
  if user.role === 'admin' → true
  if entry.visibility === 'public' → true
  if entry.visibility === 'private' → false
  if entry.visibility === 'login' → user 已登录
  if entry.visibility === 'groups' → resolveGroups(user) ∩ entry.visibleGroups ≠ ∅
```

## 4. 文章可见性

### 4.1 数据模型

`KnowledgeEntry` 新增：

```ts
/** 可见性级别：public=公开 / login=仅登录 / groups=指定组 / private=仅站主 */
visibility?: 'public' | 'login' | 'groups' | 'private'
/** visibility='groups' 时的可见组 id 列表 */
visibleGroups?: string[]
```

- 缺省（未设置）一律视为 `public`，**兼容存量数据，零回归**。

### 4.2 四级快捷 → 存储映射

| 快捷项 | visibility | visibleGroups |
|---|---|---|
| 公开 | `public` | — |
| 仅登录用户 | `login` | — |
| 指定组 | `groups` | 勾选的组 id 列表 |
| 仅站主 | `private` | — |

> 说明：「仅登录用户」等价于排除 `guest` 的全部组（含自定义组）；「指定组」即组集合白名单，体现「按用户组」语义。

### 4.3 目录「更多操作 → 权限设置」与父子同步

- `⋯` 菜单新增「🔒 权限设置」（仅站主），弹面板：
  - 四级可见性选择（选「指定组」时勾选组）
  - 同步范围选项（父文件设置后生效）：
    1. **仅本文件**：不同步子级。
    2. **只同步与父文件权限相同的子文件**：递归遍历后代，仅当某后代当前的 `visibility + visibleGroups` 与父文件**设置前**完全一致时才应用新权限；被单独自定义过的子文件保持不变。
    3. **更改所有文件**：递归全部后代统一应用新权限。
- **默认继承**：新建子文档默认复制父文档的 `visibility` / `visibleGroups`。

### 4.4 系统选项 → 文章权限批量操作

在「系统」管理页新增「文章权限」区：

- 树形列出全部文件（含层级），每项显示当前可见性。
- 勾选多篇，支持「勾选父级连带子级」。
- 统一设置为某可见性/组。
- 「指定组」模式下支持 **替换** / **追加** 组集合。

---

## 5. 用户组管理（用户 → 用户组）

`UserManager` 增加「用户组」区：

- 列出内置组（`guest`/`user`/`admin`，标记「内置，不可删」）+ 自定义组。
- 新建 / 重命名 / 删除自定义组（删除前确认；删除后组内用户回落至 `user` 组）。
- 给用户分配组（多选）。
- 组详情：预览该组可见的文档数、可见插件。

---

## 6. 插件权限迁移

- `PluginRecord.visibility: { guest, user, admin }` → `visibleGroups: string[]`。
- **迁移映射**：`guest=true → +'guest'`、`user=true → +'user'`、`admin=true → +'admin'`（默认全 true → `['guest','user','admin']`）。
- `visibleFor(groups, isAdmin)`：`enabled && (isAdmin || groups ∩ visibleGroups ≠ ∅)`。
- 角色解析扩展：`resolveRole` 保留（管理权限判断），新增 `resolveGroups`（可见性判断）。
- `PluginSettings` 可见性配置 UI：从「三角色勾选」改为「组勾选」（内置三组 + 自定义组）。
- 接口：`/api/plugins/visible`、`/api/plugins/:name/visibility`（body 由 `role/visible` 改为 `groups`）。

## 7. 关联功能改造清单（实施时一并处理）

1. **知识库读取接口按权限过滤**：`entries` / `search` / `categories` / `trash` / `comments` / `view` 等，非 admin 只返回可见范围（否则越权泄露）。
2. **前端视图过滤**：卡片流、目录树、归档、回收站、右栏「热门文章 / 最新评论 / 标签云 / 分类」。
3. **评论/评分/点赞/浏览约束**：不可见文章的评论、评分、点赞、浏览受限；「最新评论」widget 不泄露私密文章评论。
4. **插件可见性模型迁移**（见 §6）。
5. **用户模型 + 登录解析**：`User.groupIds`、`resolveGroups`。
6. **数据迁移**（见 §9）。
7. **全局搜索（Ctrl+K）**：按权限过滤。
8. **分享链接 `shareToken`**（当前未启用，已随死字段清理移除 2026-09）：`/api/share/:token` 与 `KnowledgeEntry.shareToken` 字段已删除；未来如需恢复时再定义是否绕过权限。
9. **文档同步**：实施后更新 `AGENTS.md` 数据模型、`门户布局与功能改造需求文档.md` §14 现状总览。

## 8. 数据与接口变更

### 8.1 数据模型

| 变更 | 说明 |
|---|---|
| `Group`（新） | `accounts.json` 新增 `groups: Group[]`（内置三组 + 自定义组） |
| `User.groupIds`（新） | 用户归属组 |
| `KnowledgeEntry.visibility / visibleGroups`（新） | 文章可见性 |
| `PluginRecord.visibleGroups`（替换 `visibility`） | 插件可见性组化 |

### 8.2 接口

**新增**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/groups` | 列全部用户组（站主） |
| POST | `/api/groups` | 新建自定义组 |
| PATCH | `/api/groups/:id` | 重命名组 |
| DELETE | `/api/groups/:id` | 删除自定义组 |
| POST | `/api/auth/users/:id/groups` | 设置用户组（多组） |
| PATCH | `/api/knowledge/entries/:id/visibility` | 单篇设可见性 + 同步策略 |
| POST | `/api/knowledge/batch-visibility` | 批量设可见性 |

**变更**：

- `/api/plugins/visible`、`/api/plugins/:name/visibility` → 组化。
- 全部知识库读取接口 → 增加权限过滤。
- `/api/auth/me`、`/api/auth/users` → 返回 `groupIds` / `groups`。

## 9. 迁移方案

1. `accounts.json`：缺 `groups` 时补内置三组；用户补 `groupIds = ['user']`（admin 除外）。
2. `knowledge`：存量条目 `visibility` 未设置 → 视为 `public`。
3. `plugin-registry`：存量 `visibility` 布尔 → `visibleGroups` 映射。
4. SQLite（若启用）：`entries` 加 `visibility` / `visibleGroups` 列并迁移。

## 12. 实施记录（已落地并验证）

- **权限底座**：`Group`（内置 `guest`/`user`/`admin` + 自定义组）、`User.groupIds`、`groupsOf()`、`resolveViewer`；存量 `accounts.json` 自动补齐内置组与用户 `groupIds`。
- **文章可见性**：`KnowledgeEntry.visibility/visibleGroups`（public/login/groups/private）；读取接口按 viewer 过滤（entries/categories/comments/search/view）；新建子文档继承父级可见性；`setVisibility`（self/same/all 递归）+ `bulkSetVisibility`。
- **目录权限设置**：`DocTree` `⋯` 菜单新增「🔒 权限设置」→ `EntryPermissionDialog.vue`（四级 + 组勾选 + 三选一同步）。
- **系统批量操作**：`SystemPanel` 新增「文章权限批量操作」→ `ArticlePermissions.vue`（树形勾选、父级连带子级、统一设置）。
- **用户组管理**：`UserManager` 新增用户组管理（增删改自定义组、给用户分配多组）。
- **组包含关系**：`Group.parentId`（上级组包含下级组）；`effectiveGroupsOf` 递归展开有效组；`setGroupParent` 移动父组（防环）、删除组时子组上挂；注册用户恒保留 `user` 组。

- **验证**：`pnpm -r --if-present build` + `tsc --noEmit` 通过；隔离运行时冒烟测试通过（游客/站主可见性隔离、父子递归同步、插件按组可见、内置组迁移）。
