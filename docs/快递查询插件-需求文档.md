# 快递查询插件（Express Tracker）· 需求文档

> 版本：v0.1（调研稿） · 日期：2026-11-24 · 形态：i-kit 站点插件（`panel: express`）
> 关联：`docs/快递查询插件-技术文档.md`、`docs/插件系统与权限管理体系扩展需求文档.md`

---

## 1. 背景与调研结论（先看这一节）

### 1.1 用户诉求
「输入手机号，一键查询这个手机号名下所有快递（三通一达、顺丰、京东等）」。

### 1.2 调研结论（关键）
| 结论 | 依据 |
|---|---|
| **不存在「仅凭手机号查询所有快递」的开放 API** | 快递100、快递鸟、顺丰丰桥、京东宙斯、菜鸟开放平台的查询接口，**主键都是运单号**；手机号只作为**校验项或选填项** |
| 手机号在接口里的真实作用 | 快递100 实时查询：`phone`（收/寄件人电话）**顺丰速运、顺丰快运、中通快递必填**，其他选填；快递鸟：`ShipperCode=SF/JD` 时**必填手机号后四位**；顺丰丰桥：`checkPhoneNo` 传**收/寄人任一方手机号后 4 位**；京东 `jingdong.ldop.waybill.generalQuery`：需「商家编码」或「电话（md5）」 |
| 「手机号查快递」只存在于**消费端 App**（快递100 App、菜鸟裹裹/支付宝「我的快递」） | 靠**账号绑定手机号 + 本人授权**列出该号关联包裹，**不向第三方开放**同类接口 |
| 合规红线 | 仅凭手机号批量查询他人快递属于处理他人个人信息，违反《个人信息保护法》告知同意/最小必要原则；**必须本人授权**（验证码/明确同意） |

### 1.3 由此确定的产品策略（三条路径）
| 路径 | 可行性 | 说明 | 建议 |
|---|---|---|---|
| **P0 手机号 + 运单号聚合查询** | ✅ 立即可做 | 用户输入手机号（用于校验/本人绑定）+ 运单号；插件按承运商路由到快递100/快递鸟/顺丰/京东，返回时间线 | **首期必做** |
| **P1 手机号授权绑定 → 自动列出该号包裹** | ⚠️ 需商务确认 | 快递100 企业版/菜鸟开放平台是否提供「手机号维度查件」接口需签约确认；若可用，用户短信验证码授权后自动同步 | 作为 P1，先做接口可行性验证 |
| **P2 订阅推送（状态变化通知）** | ✅ 可做 | 快递100 订阅 / 快递鸟 在途监控，回调入库并推送站内/邮件 | P1 之后 |

> 因此本期需求文档把「一键手机号查所有快递」**改写为可落地的验收口径**：*手机号用于身份/校验与本人授权，运单号用于查询；聚合多平台承运商，统一时间线*。若 P1 接口谈成，则补上「仅手机号自动列出」能力。

## 2. 目标与非目标

### 2.1 目标
- 站内提供**快递查询插件**：输入手机号（+运单号）→ 聚合查询 → 统一时间线/状态。
- 覆盖主流承运商：**顺丰、京东、中通、圆通、申通、韵达**（三通一达）+ 邮政/极兔等（由聚合平台支持列表决定）。
- **本人授权**：手机号需短信验证码验证；只允许查询绑定到该手机号的运单（或用户手动录入的运单）。
- 多 Provider 聚合与降级（快递100 / 快递鸟 / 顺丰 / 京东），**失败可切换**。
- 历史记录、手动刷新、订阅推送（P1）、用量可视（站主）。

### 2.2 非目标（本期不做）
- ❌ 仅凭手机号查询**他人**快递（合规红线，永不做）。
- ❌ 自建承运商直连（除顺丰/京东官方接口外，不爬取官网/小程序）。
- ❌ 电子面单/寄件下单（仅查询）。
- ❌ 跨境/国际快递（P2）。

## 3. 用户与权限
| 角色 | 能力 |
|---|---|
| 游客 | 仅见插件介绍与登录引导，不可查询 |
| 登录用户 | 绑定**自己的**手机号（验证码）→ 查询/刷新/订阅自己的运单；查看自己的历史 |
| 站主（admin） | 全部能力 + **Provider 配置**（密钥/默认 Provider/配额） + 全站用量统计 + 审计日志 |

约束：手机号绑定与运单归属均按当前登录用户隔离；**越权查询一律 403**；站主也不可查询未绑定用户的手机号（管理动作仅限配置与统计）。

## 4. 功能需求

### 4.1 P0：绑定与查询
| 编号 | 需求 | 说明 |
|---|---|---|
| F-01 | 手机号绑定 | 输入手机号 → 发送短信验证码（频率限制：60s/次、5 次/天/号）→ 验证成功写入绑定（加密存储） |
| F-02 | 运单查询 | 输入运单号（可多个，逗号/换行分隔，≤20/次）+ 选择/自动识别承运商 + 手机号后四位（按承运商要求自动必填） |
| F-03 | 自动识别承运商 | 优先调用聚合平台「单号识别」接口；失败时让用户手选（顺丰/京东/中通/圆通/申通/韵达/邮政/极兔/其他） |
| F-04 | 统一时间线 | 归一化状态：`已揽收 / 运输中 / 派送中 / 已签收 / 异常 / 退回`；展示节点时间、地点、描述 |
| F-05 | 多 Provider 降级 | 按「承运商 → 首选 Provider → 备用 Provider」路由；失败自动降级并记录 `provider` |
| F-06 | 刷新与缓存 | 手动刷新；缓存 TTL（默认 5 分钟，运输中 2 分钟）；缓存命中不消耗配额 |
| F-07 | 历史与删除 | 保留查询记录（默认 90 天）；用户可删除单条/全部；支持「解绑手机号」并级联删除 |
| F-08 | 错误与空态 | 无轨迹/单号不存在/手机号不匹配/配额用尽/上游超时，均有明确文案与重试入口 |

### 4.2 P1：手机号维度自动列出（需接口谈成）
| 编号 | 需求 | 说明 |
|---|---|---|
| F-09 | 授权同步 | 绑定手机号后，经用户勾选「允许自动同步该手机号包裹」→ 调用企业接口拉取该号关联运单（仅本人）|
| F-10 | 包裹列表 | 按状态分组（待收/运输中/已签收）+ 未读变化标记 |
| F-11 | 订阅推送 | 快递100 订阅/快递鸟在途监控：回调 → 落库 → 站内通知（WS `express:changed`）+ 可选邮件 |

### 4.3 站主配置
| 编号 | 需求 |
|---|---|
| F-12 | Provider 配置：AppKey/AppSecret/客户编号/回调地址；启用顺序与权重 |
| F-13 | 配额与告警：日/月查询上限、超限告警、费用估算 |
| F-14 | 审计：谁在何时查了哪个手机号/运单（脱敏） |

## 5. 数据模型（逻辑）
```
PhoneBinding   { id, userId, phoneEnc, phoneMask, verifiedAt, consentAt, status }
Package        { id, userId, bindingId, carrier, waybill, phoneTail, status, provider,
                 lastEventAt, lastSyncedAt, subscribed, createdAt }
TraceEvent     { id, packageId, time, status, location, description, source }
QueryLog       { id, userId, phoneMask, waybillMask, provider, cost, ok, errorCode, at }
ProviderConfig { id, name, enabled, weight, appKeyEnc, appSecretEnc, callbackUrl, quota }
```

## 6. 合规与隐私（硬性）
1. **告知同意**：绑定时展示《快递查询用途与隐私说明》，明确「仅查询本人运单、不查询他人、可随时撤回」。
2. **最小必要**：仅存手机号（加密）+ 运单号；不存收寄人姓名/地址全文；轨迹中的姓名/电话做脱敏。
3. **授权可撤回**：解绑即停止同步并删除关联数据（保留审计摘要）。
4. **查询鉴权**：每次查询校验 `package.userId === 当前用户` 且手机号已绑定验证。
5. **日志脱敏**：手机号/运单号仅记录掩码（`138****8888`）。
6. **留存**：原始轨迹 90 天；审计日志 180 天；到期自动清理（可配置）。
7. **反枚举**：验证码/查询接口限流 + 人机校验（连续失败触发滑块或冷却）。

## 7. UI 需求（面板 `express`）
- 顶栏：插件名「快递查询」+ 手机号状态（已绑定/去绑定）。
- 主区：**绑定卡**（未绑定）→ **查询卡**（运单号输入 + 承运商选择/自动识别 + 手机号后四位）→ **结果时间线**。
- 列表：多包裹分组（运输中/已签收/异常），卡片显示承运商图标、单号（脱敏）、最新节点、时间。
- 详情：垂直时间线，异常节点高亮；「刷新」「订阅」「删除」。
- 空态/错误/加载骨架；移动端单列；暗色主题适配。

## 8. 验收标准（AC）
| # | 验收 |
|---|---|
| AC-1 | 未绑定手机号不能查询（提示先绑定） |
| AC-2 | 短信验证码 60s 冷却、每日上限生效；错误码提示清晰 |
| AC-3 | 输入顺丰运单号 + 后四位 → 返回时间线；缺后四位时明确提示（顺丰/中通/京东） |
| AC-4 | 三通一达+顺丰+京东各至少 1 个真实单号查询成功（测试账号） |
| AC-5 | 首选 Provider 失败自动降级，响应中标注 `provider` |
| AC-6 | 越权：用户 A 无法读取用户 B 的包裹（403） |
| AC-7 | 解绑后数据不可再查、关联数据删除 |
| AC-8 | 缓存命中不重复计费；配额超限返回 429 并提示 |
| AC-9 | 审计日志可查（脱敏） |
| AC-10 | 移动端 360px 无横向滚动、时间线可读 |

## 9. 风险与未决
| 风险 | 说明 / 对策 |
|---|---|
| 无「手机号直查」接口 | 已在 §1.3 改为「手机号+运单号」；P1 与快递100/菜鸟商务确认 |
| 接口资质与费用 | 快递100/快递鸟需企业认证与预付费；顺丰丰桥需月结/客户编号；上线前确认预算 |
| 合规审核 | 需隐私政策与用户协议补充「快递查询」条款；可能需应用商店/等保评估 |
| 反爬与上游限流 | 严格超时/重试/熔断；禁止绕过官方接口爬取 |
| 短信成本 | 验证码按条计费，需限流与预算告警 |

## 10. 里程碑
1. M1（1 周）：插件骨架 + Provider 适配层 + 快递100 实时查询（三通一达/顺丰/京东）+ 绑定/查询 UI。
2. M2（1 周）：快递鸟/顺丰/京东备用 Provider + 缓存/配额/审计 + 合规文案。
3. M3（1 周）：订阅推送（P1 接口确认后）+ 全量验收 + 发版。
