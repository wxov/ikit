# 快递查询插件（Express Tracker）· 技术文档

> 版本：v0.1 · 日期：2026-11-24 · 关联：`docs/快递查询插件-需求文档.md`
> 面向 i-kit 现有架构：Cordis 3 插件 + Fastify API + Vue 3 前端（面板 `express`）

---

## 1. 总体架构

```
Vue3 前端 ExpressPanel.vue
   │  GET/POST /api/express/*   (requireUser / requireAdmin)
   ▼
Fastify 路由层 (packages/api/src/routes.ts)
   ▼
ExpressService (packages/plugins/express)     ← Cordis 插件，ctx.set('express', svc)
   ├─ ProviderRunner  ──→ 快递100 / 快递鸟 / 顺丰丰桥 / 京东宙斯（HTTP）
   ├─ SmsService      ──→ 阿里云/腾讯云短信（验证码）
   ├─ ExpressStore    ──→ data/express.json（JSON；可切 SQLite 同构实现）
   └─ ctx.emit('express:changed') → EventBus → WS 广播
```

要点：
- **插件即服务**：`apply()` 内 `ctx.set('express', service)`，与 knowledge/agent 同构；`inject` 依赖 `account`（验证码/用户）可选 `storeData`。
- **Provider 适配层**是核心：统一 `query()` 契约，承运商→Provider 路由表 + 权重/降级。
- **不落地敏感明文**：手机号 AES-256-GCM 加密，另存 HMAC 索引用于查重；日志仅掩码。

## 3. 统一 Provider 契约

```ts
export interface QueryInput {
  carrier: string          // 'SF' | 'JD' | 'ZTO' | 'YTO' | 'STO' | 'YD' | ...
  waybill: string
  phoneTail?: string       // 后 4 位（顺丰/中通/京东等要求）
}
export interface TraceNode {
  time: string             // ISO
  status: NormalizedStatus // picked | in_transit | out_for_delivery | signed | exception | returned | unknown
  location?: string
  description: string
}
export interface QueryResult {
  ok: boolean
  provider: string
  carrier: string
  waybill: string
  status: NormalizedStatus
  nodes: TraceNode[]
  errorCode?: string
  errorMsg?: string
  costCents?: number
}
export interface ExpressProvider {
  name: string
  /** 是否支持该承运商 */
  supports(carrier: string): boolean
  /** 承运商是否强制手机号后四位 */
  requiresPhoneTail(carrier: string): boolean
  query(input: QueryInput): Promise<QueryResult>
  /** 可选：单号识别 */
  detect?(waybill: string): Promise<string | null>
}
```

路由与降级：
```
carrier ─► 候选 Provider 列表（按 weight 升序）
        ─► 逐个尝试（超时 8s / 总预算 20s）
        ─► 任一成功即返回；全部失败返回最后一次错误（聚合 errorCode）
```
熔断：每个 Provider 维护 `失败计数/最近失败时间`，连续 5 次失败熔断 60s（跳过该 Provider）。

## 4. 各平台接口要点（调研）

| Provider | 接口 | 关键参数 | 手机号要求 | 备注 |
|---|---|---|---|---|
| **快递100** | `POST https://poll.kuaidi100.com/poll/query.do` | `customer`、`sign`（MD5(param+key+customer) 大写）、`param={com,num,phone,resultv2:1}` | 顺丰速运/顺丰快运/**中通**必填，其他选填 | 需企业 `customer`+`key`；订阅另用 `poll` 接口 |
| **快递鸟** | `POST https://api.kdniao.com/api/dist`（即时 1002 / 在途 8008） | `EBusinessID`、`RequestType`、`DataSign`(MD5+Base64)、`ShipperCode`、`LogisticCode`、`CustomerName` | **SF/JD 必填手机号后四位** | 免费版仅 1 年测试；正式需套餐 |
| **顺丰丰桥** | `POST https://bspgw.sf-express.com/std/service`，`EXP_RECE_SEARCH_ROUTES` | `partnerID`、`requestID`、`serviceCode`、`timestamp`、`msgDigest`(MD5+Base64)、body`{trackingType:1, methodType:1, trackingNumber, checkPhoneNo}` | **checkPhoneNo = 收/寄人任一手机号后 4 位** | 需顺丰月结/客户编号与丰桥应用 |
| **京东宙斯** | `jingdong.ldop.waybill.generalQuery` | `waybillCode`、`phone`（**md5 32 位**）、`customerCode`（二选一） | 电话需 md5 传参 | 需京东开放平台应用与商家资质 |
| **菜鸟开放平台** | `cainiao.*` 轨迹查询 | 需 appKey + 商家授权（`trace_info_query` 等） | 视接口 | 面向商家/ISV，个人开发者难开通 |

> 结论：聚合优先 **快递100（覆盖面最广、支持三通一达+顺丰+京东）**，快递鸟为备用；顺丰/京东官方接口用于「必须官方/更高实时性」的场景。**没有任何接口支持只传手机号查全部**。

- 快递鸟即时/在途：http://www.kdniao.com/file/快递鸟接口技术文档v5.12.pdf

## 5. 存储与加密

存储：`<dataDir>/express.json`（原子写 tmp+rename；文件权限 600；结构带 `version` 便于迁移）。
```jsonc
{
  "version": 1,
  "bindings": [{
    "id":"b_xxx","userId":"u_x","phoneEnc":"base64(iv|tag|cipher)","phoneHmac":"hex",
    "phoneMask":"138****8888","verifiedAt":"ISO","consentAt":"ISO","status":"active"
  }],
  "packages": [{
    "id":"p_xxx","userId":"u_x","bindingId":"b_xxx","carrier":"SF","waybillMask":"SF12****90",
    "waybillEnc":"…","phoneTail":"8888","status":"in_transit","provider":"kuaidi100",
    "nodes":[{ "time":"ISO","status":"in_transit","location":"深圳","description":"…" }],
    "lastSyncedAt":"ISO","subscribed":false,"createdAt":"ISO"
  }],
  "queryLogs": [{ "id":"q_x","userId":"u_x","phoneMask":"138****8888","waybillMask":"SF12****90","provider":"kuaidi100","ok":true,"costCents":2,"at":"ISO" }],
  "providers": [{ "name":"kuaidi100","enabled":true,"weight":10,"quotaDaily":2000 }]
}
```
加密：
- `EXPRESS_ENC_KEY`（32B hex/base64，缺失则插件拒绝启动并提示）→ AES-256-GCM，AAD 绑定 `userId`。
- `phoneHmac = HMAC-SHA256(key, normalizedPhone)` 作为唯一性索引（不存明文也可查重）。
- 运单号同样加密存储；展示用掩码；审计日志仅掩码。

## 6. API 契约

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/express/bindings/send-code` | requireUser | `{phone}` → 发送验证码（60s 冷却；日 5 次） |
| POST | `/api/express/bindings/verify` | requireUser | `{phone, code, consent:true}` → 绑定成功，返回 `{binding}` |
| GET | `/api/express/bindings` | requireUser | 我的绑定（掩码） |
| DELETE | `/api/express/bindings/:id` | requireUser | 解绑 + 级联删除名下包裹/缓存 |
| POST | `/api/express/detect` | requireUser | `{waybill}` → `{carrier}`（聚合识别） |
| POST | `/api/express/query` | requireUser | `{waybill, carrier?, phoneTail?}` → `{package, cached, provider}` |
| GET | `/api/express/packages` | requireUser | 我的包裹列表（按状态分组） |
| GET | `/api/express/packages/:id` | requireUser | 详情（时间线） |
| POST | `/api/express/packages/:id/refresh` | requireUser | 强制刷新（跳过缓存） |
| POST | `/api/express/packages/:id/subscribe` | requireUser | 订阅状态推送（P1） |
| GET | `/api/express/admin/providers` | requireAdmin | Provider 配置（掩码） |
| PUT | `/api/express/admin/providers` | requireAdmin | 更新启用/权重/配额 |
| GET | `/api/express/admin/usage` | requireAdmin | 用量与费用统计 |

请求/响应示例：
```http
POST /api/express/query
Authorization: Bearer <token>
{ "waybill": "SF1234567890123", "carrier": "SF", "phoneTail": "8888" }

200 OK
{ "cached": true, "provider": "kuaidi100",
  "package": { "id": "p_1", "carrier": "SF", "waybillMask": "SF12****123",
               "status": "in_transit", "lastEventAt": "2026-11-24T08:00:00Z",
               "nodes": [ { "time": "…", "status": "picked", "location": "深圳", "description": "已揽收" } ] } }
```
错误码：`E_NOT_BOUND`(403)、`E_PHONE_TAIL_REQUIRED`(400)、`E_CARRIER_UNKNOWN`(400)、`E_QUOTA`(429)、`E_UPSTREAM_TIMEOUT`(502)、`E_UPSTREAM_AUTH`(502)。

## 7. 缓存 / 限流 / 配额

- 缓存 key：`carrier|waybill|phoneTail`，TTL：运输中 120s、已签收 24h、异常 300s；命中写 `lastSyncedAt` 不写 `queryLogs`。
- 限流（内存 + 可选 Redis）：用户 10 次/分、50 次/时；IP 30 次/分。
- 配额：Provider 级 `quotaDaily`，超限返回 429 并告警；站主可见用量。
- 重试：仅网络错误/5xx 重试 1 次（指数退避 300ms）；4xx 不重试。

## 8. 隐私与合规实现（对应需求 §6）

| 要求 | 实现 |
|---|---|
| 告知同意 | 绑定接口必须 `consent:true`；前端展示《快递查询用途与隐私说明》 |
| 最小必要 | 只存手机号/运单号（加密）+ 轨迹；不存收寄件人姓名地址 |
| 授权撤回 | `DELETE bindings/:id` → 删除绑定 + 名下 packages + 缓存；保留脱敏审计 |
| 查询鉴权 | 每次查询校验 `package.userId === user.id`；绑定必须 `verified` |
| 日志脱敏 | 统一 `maskPhone/maskWaybill`；异常栈不含明文 |
| 留存 | 轨迹 90 天、审计 180 天（定时清理，启动+每日 03:00） |
| 反枚举 | 验证码/查询限流；连续失败 5 次进入 10 分钟冷却 |

## 9. 前端（`apps/web/src/components/ExpressPanel.vue`）

- 状态：`binding`（未绑定→绑定卡）/ `packages` / `current` / `loading` / `error`。
- 绑定卡：手机号输入 → 发送验证码（倒计时）→ 输入验证码 + 勾选同意 → 绑定。
- 查询卡：运单号（多行，≤20）+ 承运商下拉（含「自动识别」）+ 后四位（按承运商自动显示必填）+ 查询按钮。
- 列表：状态分组（运输中/已签收/异常），卡片=承运商图标+单号掩码+最新节点+时间；点击进详情。
- 详情：垂直时间线（异常高亮），操作：刷新/订阅/删除。
- 订阅（P1）：WS 监听 `express:changed` → 刷新当前列表并 toast。
- 移动端：单列、时间线可读；暗色主题；空态/错误/骨架屏。

## 10. 配置项（新增）

```bash
# ---- 快递查询插件 ----
EXPRESS_ENABLED=1
EXPRESS_ENC_KEY=            # 必填：32 字节 hex/base64（AES-256-GCM）
EXPRESS_DEFAULT_PROVIDER=kuaidi100
EXPRESS_CACHE_TTL=120       # 运输中缓存秒数
EXPRESS_QUOTA_DAILY=2000    # 每 Provider 每日最多查询
# 快递100
KUAIDI100_CUSTOMER=
KUAIDI100_KEY=
# 快递鸟
KDNIAO_EBUSINESS_ID=
KDNIAO_APP_KEY=
# 顺丰丰桥
SF_PARTNER_ID=
SF_CHECK_WORD=              # 丰桥「校验码」/密钥
# 京东宙斯
JD_APP_KEY=
JD_APP_SECRET=
# 短信
SMS_PROVIDER=console        # console | aliyun | tencent
SMS_ALIYUN_KEY_ID=
SMS_ALIYUN_KEY_SECRET=
SMS_SIGN_NAME=
SMS_TEMPLATE_CODE=
```
缺失 Provider 密钥 → 该 Provider 跳过（不阻塞插件启动）；`EXPRESS_ENC_KEY` 缺失 → 启动失败并提示（避免明文风险）。

## 11. 测试计划

1. **单元**：crypto（加解密/掩码/HMAC）、normalize（各家轨迹→状态映射）、路由降级/熔断、限流配额。
2. **Provider 契约测试**：录制各家真实响应 → mock 回放（离线 CI）；错误码映射用例。
3. **集成**：临时实例 + mock Provider HTTP（本地替身）；绑定/查询/刷新/解绑全链路；越权 403；配额 429；解绑后不可查。
4. **E2E（CDP）**：绑定→查询→时间线→刷新→解绑；移动端 360px 无横向滚动。
5. **合规用例**：未勾选同意不可绑定；日志不含明文（grep 断言）。

## 12. 运维与监控

- 指标：`express_query_total{provider,ok}`、`express_query_latency`、`express_quota_used`、`express_sms_total`、`express_cache_hit`。
- 告警：Provider 错误率 >10%（5 分钟）、配额 >80%、短信发送失败率 >5%、熔断触发。
- 日志：结构化（`provider/userId(短)/phoneMask/waybillMask/duration/ok`）。
- 费用：按 Provider 计费口径统计到 `usage` 接口，站主可查月度估算。

## 13. 上线步骤 / 回滚

1. 新增插件包与集成点 → `pnpm -r build` 全绿。
2. 配置 `.env`（Provider 密钥、加密密钥、短信）→ 本地临时实例冒烟（mock）。
3. 发版（版本号→release→tag→master→重建镜像），静态导航出现「快递查询」。
4. 回滚：`plugin-registry` 将该插件 `enabled=false` 或从默认记录移除（功能入口消失，数据保留）；`.env` 清空 Provider 密钥即降级为不可查。

## 14. 未决/风险（与需求文档 §9 对应）

- **P1「仅手机号自动列出」需与快递100/菜鸟商务确认接口与资质**；若拿不到，产品口径保持「手机号（授权）+ 运单号」。
- 顺丰/京东官方接口需企业资质与月结；若无法开通，仅用聚合平台覆盖。
- 短信签名/模板需审核；费用与限流需运营预算。
- 合规需补充隐私政策与用户协议条款（可参考《个人信息保护法》告知同意/最小必要/撤回）。
